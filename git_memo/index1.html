Git・GitHub 学習メモ

Gitでは主に以下の流れで開発を行う。 

main
 ↓
feature/○○ を作成
 ↓
作業・コミット
 ↓
mainの更新を取得(fetch)
 ↓
mainを取り込む(merge)
 ↓
mainへマージ
 ↓
push

基本コマンド

クローン

GitHub上のリポジトリをローカルへコピーする。

git clone URL
例 
git clone https://github.com/user/sample.git

ブランチ一覧

git branch
ローカルブランチのみ表示。

リモートも含めて確認する場合 
git branch -a

ブランチ作成

git switch -c feature/sample
現在のブランチを元に新しいブランチを作成して移動。

ブランチ切替

git switch main

状態確認

git status
変更・追加・削除されたファイルを確認。

コミット

git add .
git commit -m "コメント"

プッシュ

git push
ローカルの変更をGitHubへ送る。

ブランチ(branch)とは

開発用の作業場所。 

main
 ├─ feature/login
 ├─ feature/profile
 └─ feature/result

機能ごとに分けて作業することで、 複数人でも安全に開発できる。

feature/login の "/" はフォルダではない。
単なる名前の区切り文字であり、 featureブランチの子ブランチではない。

originとは

GitHub上のリモートリポジトリを表す名前。 

origin/main
origin/feature/login
origin/feature/result

これらは 「GitHubの状態を記録しているブランチ」 であり、直接編集はしない。

fetchとは

GitHub上の最新情報を取得する操作。 

git fetch

重要なのは、 現在作業中のブランチは変更されないこと。 

GitHub
 ↓
origin/main

だけが更新される。

イメージ

GitHub(main)
 ↓
fetch
 ↓
origin/main
fetch = 最新情報を取得するだけ

mergeとは

あるブランチの内容を現在のブランチへ取り込む操作。 

git merge feature/sample
現在 
main
にいる場合、 
feature/sample
 ↓
main
という形で変更が取り込まれる。

また、 
git merge origin/main
の場合は 
origin/main
 ↓
現在のブランチ
が行われる。

イメージ

origin/main
 ↓
merge
 ↓
main
merge = 取得済みの情報を取り込む

pullとは

fetch と merge をまとめて実行する操作。 

git pull
内部では概ね 
git fetch
git merge
が実行される。

イメージ

GitHub
 ↓
fetch
 ↓
origin/main
 ↓
merge
 ↓
main
pull = 情報取得 + 情報反映

他人のブランチを見る方法

最新情報取得

git fetch

リモートブランチ確認

git branch -a
例 
remotes/origin/main
remotes/origin/feature/a
remotes/origin/feature/b

ローカルへ作成して切り替え

git switch -c feature/b origin/feature/b
これで他人のブランチをローカルで確認できる。

覚えておくべき一言まとめ

  • branch ：作業場所を分ける
  • fetch ：最新情報を取得する
  • merge ：取得した情報を取り込む
  • pull ：取得して取り込む
fetch = 情報更新

merge = 情報取り込み

pull = fetch + merge
