1. Ubuntuのインストール

WSLのインストール

WindowsのPowerShellで、次のコマンドを実行する。

wsl --install

Ubuntuのインストール

次のコマンドでUbuntuをインストールする。

wsl --install -d ubuntu

2. Docker DesktopとUbuntuの連携

  1. Docker Desktopの設定（Settings）を開く。
  2. Resources → WSL Integration に進む。
  3. WSL Integrationの項目をすべてONにする（UbuntuもONにする）。

Docker連携の動作確認

Ubuntuのターミナルで、次のコマンドを実行する。

docker run hello-world

Hello from Docker! と表示されれば、Docker連携は成功。

Docker DesktopのContainers画面にも、新しいコンテナが作成されていることを確認する。hello-worldのコンテナはメッセージを表示すると終了するため、停止済みの状態で表示されていれば正常。

3. 開発ツールの共通準備

以下はUbuntu 24.04 LTS以降のBashを想定。すべてUbuntuのターミナルで実行する。WSLの場合もPowerShellではなくUbuntuを開く。Windowsに同じツールが入っていても、Ubuntu側には別途インストールする。Dockerとの連携は、以下のツールの導入には必須ではない。

sudo apt update
sudo apt install curl ca-certificates
mkdir -p ~/work
cd ~/work
  • apt updateはパッケージ一覧の更新。各apt installで表示される内容を確認してから、確認入力でYを選ぶ。
  • sudoで求められるのはUbuntuのユーザーパスワード。入力中は文字が表示されない。MiniforgeやCodexのインストーラーにはsudoを付けない。
  • WSLでの作業場所は~/workなどLinux側にすると、Linuxの権限やファイル操作を扱いやすい。
  • 外部のインストーラーは公式の配布元を確認する。ダウンロードに失敗した場合は後続を実行せず、通信環境を確認する。

4. Git

Gitは変更履歴を管理するツール。GitHubはGitのリポジトリを共有するWebサービス。

インストールと初期設定

sudo apt install git
git --version
git config --global user.name "Your Name"
git config --global user.email "YOUR_EMAIL"

名前とメールアドレスは自分のものに置き換える。コミットに記録されるため、メールを公開したくない場合はGitHubのSettings → Emailsにある自分のnoreplyアドレスを使う。名前・メールの設定はGitHubへのログインとは別。

具体的な使い方

公開リポジトリの取得例。OWNERとREPOSITORYは実際の所有者名・リポジトリ名に置き換える。

cd ~/work
git clone https://github.com/OWNER/REPOSITORY.git
cd REPOSITORY
git switch -c docs/update-memo
# ファイルを編集してから確認する
git status
git diff
# memo.txtを編集した場合の例
git add memo.txt
git commit -m "Update memo"

ここまでのコミットはローカルに保存される。非公開リポジトリの取得やGitHubへの送信には別途認証と権限が必要。Gitの基本操作のメモも参照。

5. GCC（C・C++）

build-essentialでGCC・G++・makeなどの基本的なビルドツールをまとめて導入する。

インストールと確認

sudo apt install build-essential
gcc --version
g++ --version
make --version

Cにはgcc、C++には標準C++ライブラリもリンクするg++を使う。Ubuntuで作った実行ファイルはLinux用で、Windows用のexeとは異なる。コンパイラーのバージョンはUbuntuのリリースによって異なる。

Cプログラムを作成・実行する

mkdir -p ~/work/gcc-practice
cd ~/work/gcc-practice
cat > hello.c <<'EOF'
#include <stdio.h>

int main(void) {
    puts("Hello, Ubuntu!");
    return 0;
}
EOF
gcc -std=c17 -Wall -Wextra -g hello.c -o hello
./hello

Hello, Ubuntu!と表示されれば成功。-Wall -Wextraは警告表示、-gはデバッグ情報の付加、-o helloは出力名の指定。実行時は現在のディレクトリを示す./を付ける。コンパイルに失敗したらエラーを直して再実行する。

C++の場合

cat > hello.cpp <<'EOF'
#include <iostream>

int main() {
    std::cout << "Hello, C++!\n";
}
EOF
g++ -std=c++17 -Wall -Wextra -g hello.cpp -o hello-cpp
./hello-cpp

参考：Ubuntu公式のGCC開発環境ガイド

6. Miniforge

Pythonなどの実行環境をプロジェクトごとに分けるためのツール。Miniforgeを入れるとcondaやmambaを使える。

インストールと確認

mkdir -p ~/Downloads
cd ~/Downloads
uname -m
curl -fL -o Miniforge3.sh "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname)-$(uname -m).sh"
bash Miniforge3.sh
  • WSLでもLinux用を使う。上記URLはOSとCPUを自動判定する。一般的なPCはx86_64、ARM64はaarch64。対応アーキテクチャは公式ページで確認する。
  • ライセンスを読んで同意する場合はyesを入力。インストール先は既定の~/miniforge3を想定し、最後のシェル初期化の質問もyesを選ぶ。
  • 同じUbuntuにAnaconda・Minicondaがある場合は、command -v condaで既存環境を確認する。既存のインストール先へ上書きせず、どの環境を使うか決める。

インストール後はUbuntuのターミナルを開き直して、次を実行する。

conda --version
conda info --base
conda config --set auto_activate false

自動有効化を無効にすると、次回からbase環境が自動で有効にならない。condaが見つからない場合は、既定の場所に入れたことを確認して~/miniforge3/bin/conda init bashを実行し、ターミナルを開き直す。

Python環境を作って使う

conda create -n py-study python=3.12
conda activate py-study
conda install numpy
python --version
python -c "import numpy as np; print(np.arange(5))"
conda env list
conda deactivate

[0 1 2 3 4]と表示されれば動作確認は完了。次回使うときもconda activate py-studyで有効にする。baseに作業用パッケージを集めず、用途ごとに環境を作る。UbuntuのシステムPythonを置き換えたり、sudo condaやsudo pipで環境にパッケージを入れたりしない。

環境の構成を保存・再作成する例。environment.ymlはプロジェクトのディレクトリで作成する。

conda env export -n py-study --from-history > environment.yml
# 別の環境名で再作成する場合
conda env create -n py-study-copy -f environment.yml

--from-historyは明示的に指定した依存関係を保存するため、全パッケージのバージョンを固定するものではない。参考：Miniforge公式の導入・使用手順

7. Java（OpenJDK）

Javaの開発には、実行用のjavaとコンパイラーのjavacを含むJDKを入れる。ここではUbuntu 24.04 LTS以降でOpenJDK 21を指定する。プロジェクトに指定バージョンがある場合はそちらに合わせる。

インストールと確認（Ubuntuで実行）

sudo apt update
sudo apt install openjdk-21-jdk
java --version
javac --version

両方にバージョン21が表示されれば確認完了。開発にはJREだけでは足りないため、-jdkのパッケージを選ぶ。Windows側にJavaがあっても、WSLのUbuntu側には別途インストールする。

プログラムを作成・実行する

mkdir -p ~/work/java-practice
cd ~/work/java-practice
cat > Hello.java <<'EOF'
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
EOF
javac Hello.java
java Hello

Hello, Java!と表示されれば成功。公開クラス名Helloとファイル名Hello.javaは大文字・小文字も一致させる。javacでHello.classを生成し、実行時はjava Helloのように拡張子を付けない。

複数のJavaが入っている場合

sudo update-alternatives --config java
sudo update-alternatives --config javac
java --version
javac --version

選択肢がある場合は両方ともOpenJDK 21にそろえる。JAVA_HOMEは上の実行例には不要。ビルドツールなどから要求された場合だけ設定する。次は現在選ばれているjavacからJDKの場所を求め、現在のBashに設定する例。

export JAVA_HOME="$(dirname "$(dirname "$(readlink -f /usr/bin/javac)")")"
echo "$JAVA_HOME"

毎回使う場合は上記のexport行を~/.bashrcに一度だけ追記し、ターミナルを開き直す。既存のJAVA_HOME設定がある場合は重複させず更新する。参考：Ubuntu公式のJava開発環境ガイド

8. Codex CLI

ターミナルからプロジェクトの説明、コード修正、コマンド実行などを依頼するOpenAIの開発支援ツール。

インストールと確認

公式のLinux用スタンドアロンインストーラーを使う。この方式ではNode.js・npmを別途入れる必要はない。スクリプトをダウンロードし、内容を確認してから実行する。

cd ~/Downloads
curl -fsSL https://chatgpt.com/codex/install.sh -o codex-install.sh
less codex-install.sh
# lessはqで閉じる。内容を確認したら実行する
sh codex-install.sh

完了時にPATHの設定などが表示された場合はその指示に従い、Ubuntuのターミナルを開き直す。

command -v codex
codex --version

見つからない場合はインストーラーが表示したインストール先とPATHを確認する。WSLではWindows側のCodexと取り違えないよう、command -v codexの結果も確認する。

ログインして依頼する

GitHubの節で取得したプロジェクトなど、作業したいディレクトリへ移動して起動する。以下のREPOSITORYは実際のディレクトリ名に置き換える。

cd ~/work/REPOSITORY
git status
codex

初回起動時は「Sign in with ChatGPT」など、画面に表示される認証方法を選んでログインする。WSLでブラウザーが開かない場合は、表示されたURLをWindowsのブラウザーで開く。利用できる認証方法や利用枠はアカウントによって異なるため、ログイン画面と公式ドキュメントを確認する。

起動後の入力欄で、例えば次のように依頼する。

このプロジェクトの構成と実行方法を日本語で説明してください。
hello.cに入力値のチェックを追加し、コンパイルして動作確認してください。
  • 作業前に変更をコミットするなど、戻せる状態にしておく。実行されるコマンドや承認の内容を確認する。
  • 作業ディレクトリと権限設定を確認する。通常の利用でsudo codexや承認・保護機能を無効にするオプションは使わない。
  • 依頼文やソースにAPIキー・パスワードなどを含めない。生成されたコードは確認してから利用する。

終了後はgit diffで変更内容を確認する。更新するときは同じインストーラーのダウンロード・確認・実行手順を繰り返す。参考：OpenAI公式のCodex CLI導入・使用手順
