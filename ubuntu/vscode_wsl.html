VS CodeとWSLの連携

WSL & Ubuntuの節に戻る

WindowsのVS CodeからUbuntu内のファイルを編集し、Ubuntuのコンパイラーや実行環境を使うための手順。WSL接続したウィンドウでは、ターミナルや開発用の拡張機能がUbuntu側で動く。

1. Windows側・Ubuntu側の準備

Windows側

  1. Ubuntuのセットアップを済ませ、Ubuntuが起動することを確認する。PowerShellでwsl -l -vを実行するとディストリビューション名を確認できる。
  2. VS Code公式サイトからWindows版をインストールする。追加タスクのPATHへの追加（Add to PATH）を有効にする。
  3. WindowsのVS Codeを開き、Ctrl + Shift + Xで拡張機能を表示する。
  4. Microsoft提供のWSL（拡張機能ID：ms-vscode-remote.remote-wsl）をインストールする。

この連携ではVS Code本体はWindows側にインストールする。Ubuntu側にLinux版VS Codeを別途入れる必要はない。

Ubuntu側

Ubuntuのターミナルで、接続時のダウンロードに使うツールを準備する。

sudo apt update
sudo apt install wget ca-certificates

2. Ubuntuのフォルダーを開く

Ubuntuのターミナルで、作業フォルダーに移動して次を実行する。

mkdir -p ~/work/wsl-practice
cd ~/work/wsl-practice
code .

.は現在のフォルダー。初回はUbuntu側へVS Code Serverが自動で導入されるため、ダウンロードが完了するまで待つ。インターネット接続が必要。

VS Codeから接続する場合はCtrl + Shift + Pでコマンドパレットを開き、WSL: Connect to WSL using Distro...でUbuntuを選ぶ。そのウィンドウで「ファイル → フォルダーを開く」から/home/ユーザー名/work/wsl-practiceを開く。既存のフォルダーを開いている場合はWSL: Reopen Folder in WSLでも切り替えられる。表示名は言語やバージョンによって異なる。

3. 接続確認と拡張機能

  1. VS Code左下にWSL: Ubuntuなどの接続先が表示されていることを確認する。
  2. 「ターミナル → 新しいターミナル」で統合ターミナルを開く。
  3. 次のコマンドでLinux上の作業フォルダーが表示されることを確認する。
uname -s
pwd
whoami

uname -sはLinux、pwdは/home/ユーザー名/work/wsl-practiceのようになる。Windowsの通常ウィンドウでターミナルだけUbuntuに切り替える操作とは異なり、WSL接続では拡張機能もUbuntu側の環境を利用できる。

Python、C/C++、Javaなどの開発用拡張機能は、WSL接続したウィンドウの拡張機能画面から導入する。既にWindows側へ導入済みでInstall in WSL: Ubuntuが表示された場合はそれを選ぶ。表示やテーマなど、Windows側で動く拡張機能もある。

コンパイラーやJDKなどはUbuntuセットアップの開発ツール手順に従ってUbuntu側へ入れる。PythonでMiniforgeを使う場合は、コマンドパレットのPython: Select InterpreterでUbuntu側の対象環境を選ぶ。

4. 普段の使い方

  1. Ubuntuでプロジェクトへ移動し、code .を実行する。
  2. VS Codeでファイルを作成・編集し、Ctrl + Sで保存する。
  3. 統合ターミナルでコンパイルやプログラム実行を行う。

例えばJavaの手順で作ったプロジェクトなら、Ubuntuで次を実行して開く。

cd ~/work/java-practice
code .

VS CodeでHello.javaを編集・保存したら、統合ターミナルで実行する。

javac Hello.java
java Hello

作業ファイルは~/workなどUbuntu側に置くと、Linuxのファイル操作で扱いやすい。Windows側のファイルが必要な場合は/mnt/c/...から開ける。Windows・Linuxのパスの対応関係も参照。

接続を終了するときは、コマンドパレットのRemote: Close Remote Connectionまたは「ファイル → リモート接続を閉じる」を使う。WSL接続を閉じてもUbuntu自体は停止しない。

5. うまく接続できない場合

  • code: command not found：Windows版VS CodeのPATHへの追加を確認し、Ubuntuのターミナルを開き直す。すぐに接続する場合は、WindowsのVS CodeからコマンドパレットでWSLへ接続する。
  • 左下にWSLの接続先が出ない：WSL拡張機能の有効化を確認し、コマンドパレットで接続し直す。複数のディストリビューションがある場合はUbuntuを指定する。
  • Serverの導入で止まる：ネットワーク、プロキシ、証明書の設定を確認する。コマンドパレットのWSL: Show Logからエラーを確認する。
  • javaやgccが見つからない：Ubuntu側にツールを入れたか確認する。統合ターミナルでcommand -v javaやcommand -v gccを実行し、接続先と実行ファイルの場所を調べる。
